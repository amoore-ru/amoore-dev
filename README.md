# amoore Dev — Mission Control (Clean Build v1.0)

Админка экосистемы amoore: чистый HTML/CSS/JS + Supabase. Корень репозитория — это сама админка
(`index.html`, `app.js`, `style.css`), в папке `shared/` — общее для всей экосистемы.

```
index.html · app.js · style.css     ← админка
shared/
  amoore-core.js                    ← единый скрипт для всех сайтов (эталон; копия лежит в landing и studio)
  sql/001_amoore_schema.sql         ← вся база с нуля (идемпотентная, данные не удаляет)
  edge-functions/send-telegram/     ← Edge Function для сообщений в Telegram (как было)
```

## Деплой за 4 шага
1. **Supabase → SQL Editor** → вставить `shared/sql/001_amoore_schema.sql` → Run.
   Скрипт можно запускать повторно. Старые RLS-политики он заменяет новыми, таблицы и данные не трогает.
2. Если таблица `admins` пустая: Authentication → Users → Add user, затем раскомментировать блок
   «ПЕРВЫЙ super_admin» в конце SQL (свой email + длинный токен).
3. Залить репозиторий на GitHub (хостинг как раньше).
4. Войти: email + пароль + токен доступа. Сессия хранится 6 часов, дальше достаточно одного токена.

Ключи Supabase (`URL` и `anon`) лежат в начале `app.js` и в `shared/amoore-core.js` — те же, что были.

## Вкладки
Дашборд → Медиа → Команда → Логи → Настройки (на телефоне — бургер-меню). Вкладка видна, только если у человека есть право.

## Дашборд
У каждого сайта тумблеры **Статус · Баннер** (при включении появляется поле текста). Для сайта `landing`
дополнительно **Демо-чат** и **Новости**. Под карточками — форма новостей и последние 10 с кнопкой удаления.

## Роли и права
`super_admin` (всё) · `admin` (тумблеры, новости, медиа, логи) · `moderator` (только просмотр).
В «Команда → Права» у super_admin на каждого человека 10 тумблеров, по одному на действие
(`toggle_status`, `toggle_banner`, `toggle_chat`, `toggle_news`, `manage_news`, `manage_media`,
`view_logs`, `manage_sites`, `manage_admins`, `download_backup`).
В базе хранятся только отличия от роли; «Сброс к роли» очищает их. Права проверяются и в интерфейсе, и в самой БД
(RLS + триггеры), поэтому обойти их через консоль браузера нельзя.

## God Mode
Открыть закрытый сайт: `https://сайт/?god=ТОКЕН`. Токен проверяется на сервере (RPC `verify_god`), при верном
сверху появляется золотая плашка с кнопкой «Открыть сайт». Нужно один раз на каждом домене, действует 6 часов.

## Безопасность (что изменилось)
- Колонка `admins.access_token` недоступна клиенту, токены сверяются только RPC-функциями на сервере.
- God Mode раньше принимал любой токен без проверки, теперь проверяется на сервере.
- Токены генерируются через `crypto.getRandomValues` (24 символа), в JSON-бэкап токены не попадают.

## Если что-то пошло не так
Сообщение «База не обновлена» означает, что не выполнен шаг 1. «Недостаточно прав» означает, что у роли или человека выключен нужный тумблер.
